# ACME Airlines IRROPS MVP (`v0.1.0`) Release Notes

- **Release:** `v0.1.0` (MVP Milestone & Wave-1 Hardening)
- **Date:** 2026-10-15
- **Commit Range:** Initial repository through `d706e41` ([#317](https://github.com/duboc/acme-airlines/pull/317))
- **Core Governance Rule:** **"Two Goals, One Guardrail"** — Customer recovery (`acme-customer-agent`) strictly outranks commercial revenue (`acme-sales-agent`).

---

## 1. Executive Summary

The ACME Airlines software factory has delivered and hardened the **`v0.1.0` MVP** of the autonomous flight-disruption (IRROPS) recovery and guardrailed ancillary upselling platform, together with the **Observatory** telemetry dashboard and the two-project **Scion** software factory.

Built around **Mariana Silva** (ACME Diamond tier, PNR `MSLV42`, seat `14A`, bag `BAG0001`) when flight **`AC1234` (GRU → SCL)** is cancelled at 22:03 with an onward Santiago connection (`AC0800` at 14:00), the platform detects the disruption backstage during quiet hours, rebuilds the journey across simulated enterprise MCP systems, fulfills ANAC 400 duty of care, sends a consolidated WhatsApp update at 22:09, replans conversationally (`AC1252` at 11:40), and evaluates a margin-optimized Premium Business upgrade (**$135** vs **$290** standard, **+$80** net margin) through a deterministic 6-rule guardrail before one-tap conversion and 5-system closed-loop verification.

### Scenarios 1–5 End-to-End
- **Scenario 1 (Silent Ingestion & Profile Evaluation):** Ingests the 22:03 OCC cancellation for `AC1234`, loads CRM/Loyalty/PNR context and the 14:00 SCL connection constraint, and suppresses proactive messages during quiet hours (22:00–07:00) until the journey first reaches `RESOLVED` ([#62](https://github.com/duboc/acme-airlines/pull/62) `3057dab`, [#74](https://github.com/duboc/acme-airlines/pull/74) `159e708`, [#76](https://github.com/duboc/acme-airlines/pull/76) `760f72c`).

- **6-Rule Offer Guardrail & TOCTOU Protection:** `acme.policy.guardrail_offer.evaluate` enforces `disruption_resolved`, `resolution_acknowledged`, `genuine_discount`, `margin_verified`, `zero_pressure`, and `origin_and_flight_verified` at proposal, send, and post-charge accept time under per-journey locks ([#49](https://github.com/duboc/acme-airlines/pull/49) `db99f86`, [#85](https://github.com/duboc/acme-airlines/pull/85) `cf7acaa`, [#86](https://github.com/duboc/acme-airlines/pull/86) `2ba8be6`, [#93](https://github.com/duboc/acme-airlines/pull/93) `1c9f660`).

## 4. Security

- **Per-Caller MCP Auth & Sales Route Fencing:** `acme-sim` enforces constant-time bearer auth and per-caller server allowlists (`sales` may only access `inventory`, receiving `403` everywhere else, `#27`, [#67](https://github.com/duboc/acme-airlines/pull/67) `126e12b`). Both `acme-customer` (in local mode) and `acme-sales` fail closed at startup without `ACME_SALES_TOKEN`, and `SalesRouteGuard` denies any Sales-credentialed request outside `POST /a2a` with `403` and an audit event (`#230`, [#263](https://github.com/duboc/acme-airlines/pull/263) `e76ff62`; M4 audit in [#98](https://github.com/duboc/acme-airlines/pull/98) `3c8b158`).
- **Compose Network Split & Container Hardening:** All containers run non-root (`read_only: true`, `cap_drop: ALL`, `no-new-privileges`, [#96](https://github.com/duboc/acme-airlines/pull/96) `ddc639f`). `app/compose.yaml` splits traffic across `web-net` (`10.89.1.0/24`), internal `a2a-net` (`10.89.2.0/24`), and internal `sim-net`: `customer-runtime` binds port `8800` on `10.89.1.2` (`web-net`) and its A2A-only listener (`8802`) on `10.89.2.2` (`a2a-net`), so `sales-agent` has no network route to port `8800` (`#265`, [#274](https://github.com/duboc/acme-airlines/pull/274) `73dd555`).
- **PII Redaction & Generic Error Responses:** `configure_logging()` pins third-party loggers to `WARNING+` and redacts fixture literals plus non-fixture emails, E.164 phones, PNRs, passenger IDs, and loyalty IDs across log messages, tracebacks, and exception chains (`#170`, [#179](https://github.com/duboc/acme-airlines/pull/179) `f132b2a`; `#204`, [#209](https://github.com/duboc/acme-airlines/pull/209) `a5049ee`; `#233`, [#243](https://github.com/duboc/acme-airlines/pull/243) `80706d2`). OTel span exception events are redacted (`#258`, [#261](https://github.com/duboc/acme-airlines/pull/261) `2a908ca`), and API 404/409 responses return generic messages without reflecting caller-supplied IDs (`#259`, [#264](https://github.com/duboc/acme-airlines/pull/264) `c8f7c3b`).
- **Supply Chain & Secret Hygiene:** Upgraded `google-adk` to `1.39.1` for `CVE-2026-4810` (`#241`, [#256](https://github.com/duboc/acme-airlines/pull/256) `a7700c1`); enforced full commit-SHA GitHub Action pins (`action-pins`), Dependabot, and Trivy secret + critical-CVE scans (`#234`, [#239](https://github.com/duboc/acme-airlines/pull/239) `92b8492`; updates in [#247](https://github.com/duboc/acme-airlines/pull/247) `84c19b1`, [#272](https://github.com/duboc/acme-airlines/pull/272) `43fc04e`); moved org/billing/domain settings to gitignored `infra/factory.local.env` ([#292](https://github.com/duboc/acme-airlines/pull/292) `ab485f0`).

## 7. Upgrade Notes (New Required & Runtime Environment Variables)

1. **`ACME_SALES_TOKEN` is now required in local and Compose modes (`#230`, [#263](https://github.com/duboc/acme-airlines/pull/263)):** `acme-customer` (when `ENGINE_MODE != "agent-engine"`) and `acme-sales` refuse to start (`SystemExit`) if `ACME_SALES_TOKEN` is unset. Set it alongside `ACME_SIM_TOKENS`:
   ```bash
   export ACME_SIM_TOKENS="customer=$(openssl rand -hex 24),sales=$(openssl rand -hex 24),test-admin=$(openssl rand -hex 24)"
   export ACME_SALES_TOKEN=$(echo "$ACME_SIM_TOKENS" | sed -n 's/.*sales=\([^,]*\).*/\1/p')
   ```
2. **A2A Listener & Compose Network Split (`ACME_A2A_HOST`, `ACME_A2A_PORT`, `#230`, `#265`, [#274](https://github.com/duboc/acme-airlines/pull/274)):** `acme-customer` serves passenger routes on `ACME_CUSTOMER_HOST:ACME_CUSTOMER_PORT` (`10.89.1.2:8800` on `web-net`) and `/a2a` on `ACME_A2A_HOST:ACME_A2A_PORT` (default `8802`; `10.89.2.2:8802` on internal `a2a-net`). Point `ACME_CUSTOMER_URL` on `acme-sales` at port `8802` (now the default).
3. **Background Loop & Read-Only `GET`s (`ACME_CUSTOMER_LOOP`, `#228`, [#267](https://github.com/duboc/acme-airlines/pull/267)):** `ACME_CUSTOMER_LOOP` defaults to `1`. HTTP `GET /journeys/{id}` and `GET /whatsapp/{id}/messages` no longer trigger `tick()`; set `ACME_CUSTOMER_LOOP=0` only in tests that step the clock manually.
4. **Bounded Vertex Calls (`LLM_TIMEOUT_SECONDS`, `#231`, [#271](https://github.com/duboc/acme-airlines/pull/271)):** Defaults to `8.0`s per `VertexLlm` call (template fallback on compose, fail-closed `Other` on parse).
5. **Agent Engine Env Vars (`ACME_STATE_DB`, `ACME_ENABLE_TRACING`, `ACME_TRACE_SAMPLER`, `ACME_GENAI_PROJECT`, `ACME_GENAI_LOCATION`):** Configured automatically by `python -m acme.engines.deploy` (`GOOGLE_CLOUD_*` names are reserved by Agent Engine, `#190`).
6. **Factory Local Secrets (`infra/factory.local.env`, [#292](https://github.com/duboc/acme-airlines/pull/292)):** Move `ORG_ID`, `BILLING_ACCOUNT`, `PO_EMAIL`, and `WEB_DOMAINS` into gitignored `infra/factory.local.env`.

## 8. Known Risks & Open Follow-Ups

- **Untrusted Dependabot PR Policy ([#257](https://github.com/duboc/acme-airlines/issues/257)):** Dependabot PRs `#248`–`#254` (including major bumps `mcp` 1.30 → 2.3, `typescript` 6 → 7, `eslint` 9 → 10) are authored by `app/dependabot` and remain untouched under the factory's trusted-author rule until the product owner selects a handling policy.
- **Agent Engine Shared Identity & Per-Worker Replay Tape ([#279](https://github.com/duboc/acme-airlines/issues/279), [ADR 0103](../decisions/0103-stateless-engine-scenarios.md)):** Both Reasoning Engines run as `acme-agent-engine` (fenced in code by `EngineCustomerClient` and `test_architecture.py`), and `RecordingLlm` is per worker process: if the Sales tick (`a2a_skill`) runs on a different worker/container than the next Customer call, a cross-container rebuild replays the offer message with `FakeLlm` (`tape_miss > 0`, accepted by the PO in `#279` / [#315](https://github.com/duboc/acme-airlines/pull/315)).
- **In-Flight Wave-1 Hardening & Bug Issues:** SQLite `SharedState` concurrent write stress hardening ([#288](https://github.com/duboc/acme-airlines/issues/288)), SSE client-disconnect loop cleanup in `agent-engine` mode ([#305](https://github.com/duboc/acme-airlines/issues/305)), `POST /api/scenarios/{id}/step` transient Sales/state RPC error handling ([#306](https://github.com/duboc/acme-airlines/issues/306)), CI backend test parallelisation ([#282](https://github.com/duboc/acme-airlines/issues/282)), and the milestone-wide security audit ([#283](https://github.com/duboc/acme-airlines/issues/283)).
- **Multi-Service Cloud Run Target Gaps (`docs/product/deploy.md`):** While the single-container `acme-irrops-demo` and Agent Engine deployments are live, a split 4-service Cloud Run deployment still tracks follow-ups for `X-Serverless-Authorization` ID tokens (`#100`), `/a2a` caller SA checks (`#101`), and remote `acme-sim` connectors in `CustomerRuntime` (`#102`).
